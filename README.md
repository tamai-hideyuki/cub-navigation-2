## 解決してる問題：125cc以下のバイクで、通れない道に入らずに、知らない道を走れる様にすること

### このアプリについて
パソコンで、通れない道を消した地図を作成する部分と、iPhoneで、その地図だけを使って案内する部分の二つでできています。

### 全体の考え方
- 125cc以下が通れない道は、地図のデータそのものから消しておく。これによって、iPhoneの計算は、消した後の地図しか知らないので、どんなルートを計算しても通れない道は通らない
- iPhone側は、通信を使わない：ルートの計算も地図の表示も、iPhoneの中に入れたデータだけで行う（これによって、圏外でもリルートできる）

### PC側
地図を作り直す時にだけ動かす
1. 地図のデータを取って切る（prepare.sh、make_area.py）
- OpenStreetMap（OSM）の関西のデータを Geofabrik から取り、7府県の境界（外側に 2km の余白）で切る
2. 通れない道を消す（select_removals.py）
- 消し方は三段階
    - 道の種類：高速道路・自専道・有料道路・フェリー
    - OSMの規制のタグ：二輪・原付の通行止め、車の通行止め、時間帯つきの規制、決まりに無い値
    - ClaudeCodeで作った一覧：（blocklist.json）：二輪車協会の一覧と県警の交通規制のデータを突き合わせて、OSM に書かれていない規制を根拠つきで入れたもの
        - 逆に、怪しいけれど調べて通れると分かった道は allowlist.json に入れる
3. タイルを作る
- ルート用：道のつながりのデータ。Docker の Valhalla で作る
- 地図用： 画面に描く道・川・地名の形。Planetiler で作る（build_map.sh）
4. 確認する
- 決まった地点の組（大阪駅 → おかげ横丁など）でルートを引き、消した道を1本も通らないことを確かめる
- ※ できたタイルは、macからiPhoneのアプリの中へ写す

### iPhone側（app/）
- Expoアプリで、３つの層に分けている
1. 画面（src/screens/）
- 目的地を決める画面（PlanScreen.tsx）
- 走行中の画面（RideScreen.tsx）

2. 走行中の処理
- iosから届く１秒ごとの現在地を受け取って、以下のことを実行する
    - ナビの本体を進めて、鳴らす案内があれば音声を鳴らす
    - 道を外れたと判断したら、現在地と進んでいる向きから計算し直して、「ルートを計算し直しました」という音声を鳴らす（３０秒おきまで）
    - ルートと進み具合をファイルに残す（アプリが落ちても、開き直せば続きから案内できるように）
    - 目的地に到着して２分経ったら、位置の取得を停止する

3. 計算と地図
- ルートの計算（modules/cub-routing/）
- 地図の表示（MapLibre が、iPhone の中の地図のタイルを描く）
- 音声（assets/voice/）

## 中心にある「ナビの本体」（src/navigation/）
- 現在地を受け取って、ルートのどこまで進んだか、ルートから外れていないか、次の曲がるところまで何mかを判断する
- 曲がる所の 300m 手前と 50m 手前で、鳴らす案内を返す
- 画面・声・GPS に一切依存しない、ふつうの TypeScript で記述している


# 一回の走行の流れ
1. 地図を長押し → 現在地から目的地まで、iPhone の中の Valhalla でルートを計算
2. 「案内を始める」→ 走行の処理が位置を受け取り始める
3. 位置が来るたびに、ナビの本体が判断 → 曲がる所の手前で声を鳴らす
4. 道を外れると → その場で計算し直して、新しいルートで案内を続ける
5. 着くと「目的地に着きました」→ 2 分後に位置の取得を止める
